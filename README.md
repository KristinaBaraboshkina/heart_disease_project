## Датасет

**UCI Cleveland Heart Disease Dataset** — 303 наблюдения, 13 признаков.

| Признак | Описание | Тип |
|---|---|---|
| `age` | Возраст | Числовой |
| `sex` | Пол (1=муж, 0=жен) | Категориальный |
| `cp` | Тип боли в груди (0–3) | Категориальный |
| `trestbps` | Давление в покое (мм рт. ст.) | Числовой |
| `chol` | Холестерин (мг/дл) | Числовой |
| `fbs` | Сахар натощак > 120 мг/дл | Категориальный |
| `restecg` | Результат ЭКГ (0–2) | Категориальный |
| `thalach` | Макс. ЧСС | Числовой |
| `exang` | Стенокардия при нагрузке | Категориальный |
| `oldpeak` | Депрессия ST | Числовой |
| `slope` | Наклон ST (0–2) | Категориальный |
| `ca` | Кол-во крупных сосудов (0–3) | Числовой, есть пропуски |
| `thal` | Тип таласемии (3/6/7) | Числовой, есть пропуски |
| `target` | 0 = нет болезни, 1 = болезнь | Целевая переменная |

**Баланс классов:** 54.1% / 45.9% — приемлемый, особых мер не требует.

## Методы отбора признаков

Сравнивались три подхода, все встроены в `Pipeline`:

| Метод | Класс | F1 test | CV F1 |
|---|---|---|---|
| **Filter (SelectKBest)** | `SelectKBest(f_classif, k=10)` | **0.667** | **0.637** |
| Wrapper (RFE) | `RFE(LogReg, k=10)` | 0.625 | 0.584 |
| Embedded (L1) | `LogReg(penalty='l1', C=0.5)` | 0.583 | 0.621 |

Победил **Filter-метод**: быстрый, масштабируемый, лучший CV F1.  
Топ-признаки по ANOVA F-score: `exang`, `ca`, `sex`, `thalach`, `age`, `oldpeak`.

| Модель | F1 | ROC-AUC | PR-AUC | Recall | CV F1 |
|---|---|---|---|---|---|
| **LogisticRegression** | **0.667** | 0.694 | 0.725 | 0.607 | **0.624** |
| GradientBoosting | 0.654 | 0.772 | 0.754 | 0.607 | 0.505 |
| RandomForest | 0.609 | 0.745 | 0.691 | 0.500 | 0.571 |

Финальная модель: **LogisticRegression** с `GridSearchCV`.  
Параметры: `C=0.1`, `penalty=l2`, `solver=liblinear`, `k=12`.

## Финальные метрики

```
              precision    recall  f1-score   support
  No disease       0.71      0.82      0.76        33
     Disease       0.74      0.61      0.67        28
    accuracy                           0.72        61

ROC-AUC : 0.686
PR-AUC  : 0.726
F1      : 0.667

Confusion Matrix:
  TN=27  FP=6
  FN=11  TP=17
  Recall (болезнь) = 0.607
```

**Почему F1, а не Accuracy:** при медицинской диагностике пропущенный больной (FN) опаснее ложной тревоги (FP). F1 учитывает оба типа ошибок.

## Запуск через Docker

```bash
# Сборка образа
docker build -t heart-disease-ml .

# Запуск (модель и метрики сохраняются на хосте через volume)
docker run \
  -v $(pwd)/models:/app/models \
  -v $(pwd)/mlruns:/app/mlruns \
```

После запуска в `models/` появятся:
- `pipeline.pkl` — обученная модель
- `metrics.json` — F1, ROC-AUC, PR-AUC, Recall, Precision

Переменные окружения (переопределяются при `docker run -e`):

| Переменная | По умолчанию | Описание |
|---|---|---|
| `DATA_PATH` | `/app/data/heart.csv` | Путь к данным |
| `MODEL_DIR` | `/app/models` | Куда сохранять модель |
| `MLFLOW_URI` | `/app/mlruns` | Tracking URI для MLflow |
| `EXPERIMENT` | `heart-disease-docker` | Название эксперимента |

## Этические аспекты и безопасность

### Этика применения модели

**Чувствительность данных.** Медицинские данные относятся к специальным категориям персональных данных. По ФЗ-152 и GDPR их обработка допустима только при наличии явного согласия пациента и с указанием цели («обучение модели»).

**Выбор метрики.** Для диагностической задачи Recall важнее Precision: пропустить больного человека (FN) опаснее, чем направить здорового на дообследование (FP). Текущий Recall = 0.607 — модель пропускает ~39% больных, что недопустимо в реальной клинической практике без дополнительной валидации.

**Предвзятость модели.** Датасет Cleveland собран в 1988 году, преобладают мужчины (68%). Модель может хуже работать на женщинах и других популяциях. Перед продакшн-деплоем необходим аудит по демографическим группам.

**Ответственность.** Модель является вспомогательным инструментом, а не заменой врача. Решения, влияющие на здоровье человека, не должны приниматься автоматически — требуется человеческий контроль (принцип из ФЗ-152, ст. 16).

### Безопасность ML-пайплайна (MLSecOps)

| Этап | Меры |
|---|---|
| Данные | Анонимизация перед обучением; `SimpleImputer` только на train (нет data leakage) |
| Признаки | `handle_unknown='ignore'` — защита от неизвестных категорий в продакшне |
| Модель | Версионирование в MLflow Model Registry; `joblib` + фиксация версий библиотек |
| Контейнер | `python:3.11-slim` минимизирует attack surface; секреты не в коде и не в образе |
| Мониторинг | `metrics.json` для CI/CD gate; рекомендуется мониторинг data drift в продакшне |
